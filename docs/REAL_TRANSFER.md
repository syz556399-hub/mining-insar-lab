# 真实条纹分割：标签与实验约定

## 目标与标签

主要输出为**完整的矿区沉降条纹异常区域**，相连、重叠盆地合并为语义区域。确认的小目标保留，不用最小面积筛选自动删除。

潜在外围影响区应单独显示为不确定推断；不能通过膨胀掩膜就宣称获得物理影响范围。当前合成标签仍是垂直沉降增量阈值，不等于人工判断的可见条纹边界。此版本没有偷换该定义。

真实训练标签必须区分：已确认目标、完整核查的背景、忽略区域。未圈出的像素不能自动当作可靠背景。中心条纹不清楚时，建议暂列忽略区域，待逐例核查后确定；不能仅从显示颜色推断相干性或失相干原因。

## 显示影像的边界

对只有 BMP 的数据，先核验原始调色板及切片坐标，记录导出软件与流程是否已知。软件名本身不能提供数值相位、雷达几何、地理像元间距或相干性。显示码输入只是代理输入，不能冒充校准相位。

重叠切片中的标注先按全图坐标取并集，同时记录相互不一致的位置。不一致是核查提示；不自动判定某张标注错误，不自动填洞或删除碎片。连通区域数量不等于真实矿区数量。

## 两条对照路线

1. 纯合成训练，在合成验证集上选模型，固定后检验真实影像。
2. 从同一合成预训练模型出发，使用少量**已经核实**的真实标签微调。

两路使用相同模型结构、输入编码、输出规则和独立保留的真实测试日期。阈值和尺度只能在开发/验证数据上选择；不得依据测试结果继续调整。汇报 IoU、精确率、召回率和按目标大小分组的覆盖情况，兼顾误检与漏检。

同一矿区的多个日期仍存在空间和时间相关性。需按日期对、共享影像日期及空间重叠关系管理划分；已经反复观察的日期是开发集，不能重新命名为盲测集。结果只能支持同矿区跨日期表现，不能直接声称跨矿区泛化。

## 本地核查工作流

```sh
python annotation_audit.py --labels data/labelme_scene --source data/scene.bmp --out runs/label_audit
python scale_audit.py --labels data/labelme_scene --source data/scene.bmp \
  --run runs/predict_scale1 --run runs/predict_scale2 --out runs/label_audit
```

导入器目前仅支持 manifest 描述的切片与 LabelMe 的单类 `mask` 形状（类别 `1`）；其他标注格式会明确拒绝。原图与所选切片逐像素检查一致后生成报告。抽样按标注面积确定，不按预测好坏筛选。

检查页默认全部待核实，提供结论、背景核查复选框和备注。下载的 JSON 绑定原图与标注校验值，**不改写原始标注，也不会自动启动训练**；刷新前应下载保存。修正边界和忽略区仍需在标注工具完成，忽略区导入尚未实现；用户已确认的最终标注可使用文末的真实微调流程。

要从界面进入，可在 `runs/audit_latest.json` 写入 `{"audit":"runs/label_audit"}`。服务只允许该指针指向项目 `runs` 内部。原始数据、检查页、模型权重和真实结果不进入公共源码包。

## 尺度诊断的解释

固定模型、阈值和输入编码，分别比较原图与不同缩小倍数。尺度只代表像素上下文，没有像元间距时不换算为米。面积除以缩小倍数平方只是尺寸风险提示，不是信息保留量的实测。

保存切片的覆盖范围尚未完整核查时，表中指标称为“与现有标注的一致性”，不是可信的真实精度。另列去除重叠标注不一致位置的结果作为敏感性分析；不能靠排除困难像素证明模型有效。

## 用户确认最终标注后的执行方式（2.8）

本节覆盖上文“待核实”流程：当数据所有者确认 LabelMe 范围和对象记录为最终标注时，直接采用原始文件监督，无需重复填写检查表。

`real_labels.py` 对每个文件独立解码，保留掩膜孔洞、小目标和 shape 索引、类别、group_id。每个文件的多个 mask 取像素并集只用于语义分割，原始对象列表另存；不会用连通域数替代对象数。跨切片重复视图没有可靠统一 ID 时，不声称得到整景独立对象总数。

未标注像素在这些已保存的最终标注切片内作为背景；没有标注文件的切片不参与监督。相邻切片保持各自标签，既不按跨切片并集扩张某张标签，也不因差异自动删除监督像素。

两路对照先固定原始像素尺度与块大小，记录纯合成预训练模型的开发验证基线，再做少量真实数据微调。训练采用真实标签选取的目标附近裁块和均匀裁块交替，加同步空间翻转；验证按不重叠裁块遍历每张切片，填充区域排除。不同原始切片的重叠视图会分别计入，所以这是切片级像素统计，不是整景去重统计。

```sh
python finetune_real.py --checkpoint runs/synthetic/best.pt \
  --train-labels data/train_labels --train-source data/20250101_20250113.diff.bmp \
  --val-labels data/val_labels --val-source data/20250301_20250313.diff.bmp \
  --out runs/real_finetune --epochs 6 --size 256 --draws 4
python real_report.py --run runs/real_finetune --initial runs/synthetic/best.pt \
  --labels data/val_labels --source data/20250301_20250313.diff.bmp
```

模型按开发验证集 IoU 选择，未微调基线也可胜出；并报告精确率和召回率以识别全部预测背景的退化。学习日志与第一步梯度/参数变化一并保存。训练、验证不能共享源文件或采集日期；同矿区空间相关性仍然存在。

当前模型学习的是二值语义分割，不是实例分割或独立的数量回归。真实微调不证明合成器已获得物理校准。新的微调模型保留零亮度位置的标签和预测，不再把零显示码自动当作必须清除的区域；零输入向量只是缺少可读显示颜色，不是水体判据。
